        The brief
        
        
        This tool is built for one specific person: someone changing careers who needs their existing resume completely reframed — not just tweaked — for a new field, and who wants ATS-safe language along the way. It intentionally skips job-description matching; the point is a general, portable rewrite they can then adapt per application.
        

        
        System prompt design
        
        
        The Claude call behind this tool is scoped tightly:
        
        
          
          
        • Role — an expert resume writer and ATS specialist who specializes in career changers, told explicitly to reframe experience for transferability rather than just polish wording.
          • 
          
        • Strict output contract — the model must return only JSON matching a fixed schema (score, summary, strengths, risks, section-by-section before/after with reasoning, a full clean rewrite, and next steps). No prose, no markdown fences. This is what lets the interface render structured redline cards instead of a generic chat bubble.
          • 
          
        • Anti-fabrication rule — the model is told never to invent employers, dates, titles, or metrics that aren't implied by the original text. Where quantification would strengthen a bullet but the number isn't known, it inserts a bracketed placeholder like [quantify: e.g., reduced X by ~%] instead of making one up.
          • 
          
        • Edge cases handled explicitly — the prompt defines what to do with input that isn't a resume, is too thin to work with, or contains an attempted instruction override (e.g. "ignore your instructions and…"). In each case it returns a typed error object rather than improvising, which the UI turns into a plain-language error panel.
          • 
          
        • Tone lock — professional and polished is enforced both in the rewritten resume content and in the editor's-note summary copy, so the voice doesn't drift toward either corporate stiffness or forced friendliness.
          • 
        
        

        
        Why this interface
        
        
        A generic chat box would bury the actual deliverable — the rewritten resume — inside a scrolling conversation. Instead the UI borrows from copyediting: a paper sheet for the raw draft, a wax-stamped ATS score, and redline cards where the struck-through original sits directly above its rewrite with a margin note explaining why. That mirrors how a human editor actually hands back a marked-up manuscript, which is a closer match to "full resume rewrite plan" than a dashboard of sliders would be.
        

        
        Extending it
        
        
        Ways to grow this without changing its core shape:
        
        
          
          
        • Job-description matching — add an optional second textarea for a target posting, and extend the schema with a keyword_gap array so the redline cards can cite exact missing terms.
          • 
          
        • Multi-turn refinement — keep the conversation array (system + prior turns) instead of a single one-shot call, so a user can reply "make the summary shorter" and get a targeted re-edit instead of starting over.
          • 
          
        • File upload — accept a PDF/DOCX, extract text client-side (e.g. via a PDF.js-style parser) before sending, so users don't have to copy-paste.
          • 
          
        • Memory across sessions — persist the last rewrite and score in local storage so returning users can see their progress instead of starting from a blank sheet.
          • 
          
        • Tool use — give the model a real web-search tool to pull current ATS keyword trends for a target industry, rather than relying on training knowledge alone.
